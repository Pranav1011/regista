# Roadmap

Each phase ends with something a recruiter can see and a number they can
trust. A phase is done only when its numbers come out of `eval/` with one
command.

## Phase 1: Tactical analytics on open tracking data (done)

No computer vision, no LLM. Prove the analytics on clean data first.

Done when:
- Metrica sample games 1–3 and the SkillCorner open matches load into
  canonical parquet via kloppy, passing `validate_frames`.
- Kinematics (smoothed velocity, speed) computed with implausible values masked.
- Possession and pass inference from tracking alone, scored against Metrica's
  labelled PASS events (precision / recall / F1, game 3 held out).
- Formation and role detection per team per time window, in and out of
  possession, with change-point flags; roles checked against SkillCorner's
  listed player positions.
- Team shape metrics: defensive line height, length, width, compactness.
- Pass networks from inferred passes, compared with networks from real events.
- **Passing options:** pitch-control model estimating the success probability
  of a pass to each teammate. Calibration against real completed vs failed
  passes on the held-out game (reliability diagram + Brier score).
- `eval/reports/phase1.md` generated by `uv run python eval/phase1.py`.

## Phase 2: Analyst agent + viewer v1 (current; first public demo)

An analyst agent grounded in the Phase 1 analytics, and a viewer anyone can
open in a browser. No computer vision. Plan: `docs/KICKOFF_PHASE2.md`.

Principles: a deterministic core with the LLM at the edge (the LLM never
computes a number); every answer carries evidence (match, period, frame range,
clock); live means causal (detectors see only data up to the current frame);
one tool layer serves MCP, the agent loop, and the evals; zero cost (local
Ollama models, static hosted demo); prompts, thresholds, and templates are
designed on Metrica games 1-2 and evaluated once on game 3 (corrected labels)
and SkillCorner.

Done when:
- **Match store:** `regista build-store` precomputes frames, possession, v2
  passes, formation and shape windows, pass networks, and pitch control at pass
  moments (with the Platt display probability) into parquet with a manifest;
  queried with DuckDB; store reads equal direct computation.
- **Pressing:** fixed a-priori thresholds (primary pressure = defender within
  5 yd / 4.57 m, after StatsBomb's pressure definition; "tight" pressure at 2 m;
  defenders counted within 4.57 m); press intensity per window and pitch third;
  sanity check against Metrica CHALLENGE + RECOVERY counts, reported as such.
- **Moment detectors:** streaming and causal (back-line change on
  out-of-possession windows, press change, line-height shift), persistence in
  minutes on 1-minute-step trailing windows, thresholds frozen on games 1-2 for
  about 4-8 alerts per match. A count above 12 is reported, never truncated.
  Causality and known-answer tests. Alert counts and detection delay for game 3
  and every SkillCorner match.
- **Tools + MCP:** typed read-only tools with evidence and reliability signals,
  validated match-clock times, explicit "not available" for unsupported
  questions; a stdio MCP server with docs and a test.
- **Agent loop:** provider interface with Ollama; answer schema with citations
  and caveats; deterministic number-grounding check (retry once, else mark
  unverified). Model chosen on the dev set among llama3.1:8b (baseline),
  qwen3.5:9b, gemma4:12b, and gpt-oss:20b if it runs acceptably in 18 GB.
- **Agent eval:** template-generated questions with answers computed from the
  store (lookup, comparison, temporal, multi-step, unanswerable, reliability);
  accuracy per category, tool selection, citation validity, number grounding,
  abstention, latency; match summaries judged by a model from a different
  family (pairwise, both orders), with 30 human labels for judge agreement.
  Dev on games 1-2; one frozen test run on game 3 + SkillCorner.
- **Viewer v1 (static, Vite + TypeScript):** 10 fps replay, pitch with
  non-colour team cues, passing-option arrows (Platt probability, "model
  estimate"), causal formation cards with runner-up and margin, causal alert
  timeline ranked by severity with "show all", chat panel with pre-generated
  answers (local free-form mode via `regista serve`), visible credits.
- **Deploy:** GitHub Pages workflow (enabled by the maintainer), README demo
  link and GIF, generated Phase 2 results; ADRs for the store, causal detectors,
  number grounding, model choice, and the static demo.

## Phase 3: Perception

- **Detector benchmark:** Ultralytics YOLO vs RF-DETR, both fine-tuned on free
  football datasets using free Kaggle/Colab GPU sessions. Report mAP (ball
  reported separately), and fps on a T4. Use the winner; publish the comparison.
- Tracking via `supervision` (ByteTrack), team assignment by embedding
  clustering, pitch keypoints plus per-frame homography to canonical frames.
- Benchmarked locally on SoccerNet Game State Reconstruction (GS-HOTA).
  NDA data never leaves the machine.

## Phase 4: Live overlays + viewer v2

- Overlays projected onto video via inverse homography: red home / blue away
  markers, ball-carrier marker, team shape lines, passing-option arrows with
  probabilities, pressing indicators.
- Visibility gating: passing options and pitch control grey out when too few
  players are visible. Always show "visible N of 22".
- Near-real-time replay at native frame rate with a stated latency budget;
  detection every N frames with tracking in between. Report dropped frames.
- Pause overlays during replays and close-ups (shot-type detection).
- Viewer v2: video with overlays in place of the animated pitch.

## Phase 5: Real team, real footage

- Film a local or club team from a fixed elevated camera.
- Deliver post-match reports; log coach feedback and what changed because of it.
- Record the demo reel on this footage (the only video we can show publicly).

## Recruiter-facing deliverables (updated each phase)

- README opens with a 60–90 s demo video/GIF and a live demo link.
- Results table: every number linked to the eval script that produced it.
- `docs/DESIGN.md` with key decisions and trade-offs (short ADR entries).
- One write-up per phase for LinkedIn and the portfolio site, including what
  didn't work and why.
